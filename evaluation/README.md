# OntoCare 30 Case 端到端评测材料

本目录保存一轮线上 Demo 评测快照：30 个场景、35 轮用户输入。用例、案例结果和逐轮结果分别存放在 `cases_30.json`、`results_30_cases.csv`、`results_35_turns.csv`。

- 结果摘要：15 PASS、9 PARTIAL、6 FAIL。
- 评测记录与解释：[飞书评测报告](https://ecn3a0t0ngi7.feishu.cn/docx/FKO8dou0EoYUujxfOgrcbP52n8b)
- Demo：[Railway 在线体验](https://web-production-94c004.up.railway.app/)
- 源码：[GitHub 仓库](https://github.com/jiangenjing/ontocare-demo)

## 文件说明

### `cases_30.json`

30 条评测场景的输入轮次、类别、预期检查和关键安全要求。它用于说明评测覆盖范围，不是客户真实会话，也不等同于仓库 `eval.py` 的 30 条规则函数断言。

### `results_30_cases.csv`

按 Case 汇总的实际终轮结果，包含模型状态、产品/订单/保修/经销商状态、知识命中、动作空间、规则原因、响应时延、预期检查、评分和人工备注。

### `results_35_turns.csv`

每一轮的用户输入和系统回复、HTTP 状态、当前阶段、产品/订单/知识/动作与规则状态。用它检查多轮状态有没有在中途丢失，而不是只看最后一条回答。

## 方法与判定口径

评测按服务任务拆分覆盖类别，包含产品歧义、订单查询与查无、保修、经销商国家/卖家匹配、知识检索、排障、退款/换货约束、投诉与情绪、服务边界、物流、无关问答、问候/结束语，以及多轮补槽和上下文保持。每条用例设置场景化关键检查，不要求模型输出唯一固定句子。

判定优先级为：

1. **安全边界**：不伪造订单、保修或经销商状态；不把 UNKNOWN 当过保；不宣称真实退款、换货、补发或转接已经完成。
2. **业务状态**：正确识别/澄清对象，按可用证据推进订单、知识、规则和案件阶段；区分用户陈述、测试数据和待核验凭证。
3. **多轮连续性**：跨轮保留当前产品、问题、槽位和已尝试步骤；用户纠正或改变诉求后更新后续判断；结束语正确结束而不把“没有订单”误当告别。
4. **回复和展示**：下一步清楚、措辞不过度承诺，右侧证据、阶段与动作状态不和文字回复冲突。

**PASS** 表示关键预期满足；**PARTIAL** 表示安全核心成立，但一项或多项任务完成度、追问、上下文或展示不完整；**FAIL** 表示关键业务/安全预期未满足。此分级是人工基于记录的场景判断，后续如果修改评分契约，应保留旧记录并标清口径变化。

## 结果如何阅读

15/30、9/30、6/30 是这一轮演示环境和这一份用例集的案例分类计数，不是长期准确率、客户满意率、置信区间或生产服务等级。案例包含多轮任务，35 轮不能直接用作 35 个独立样本；评测规模和类别分布也不足以证明对所有售后问题的泛化能力。CSV 中保留逐轮数据和备注供评委核查。所有涉及退款/换货的写操作均未真实执行。

在公开使用前请检查 CSV 中没有新加入的真实姓名、邮箱、订单、地址或密钥。此目录当前数据是模拟评测记录。线上评测不会连接 Anker 官方订单或服务系统。
